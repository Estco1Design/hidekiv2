# HIDEKI — аудит и выполненные изменения

## Вывод

Исходник имел подходящую визуальную основу, но не был рабочим сайтом для получения заявок. Исправлена техническая основа и выстроен путь клиента. Конкурентоспособность нельзя подтвердить по коду: нужны сильные реальные серии, понятный оффер, доказательства работы и тестирование на посетителях. Публикация не выполнена.

## Исправления

| Проблема исходника | Изменение |
|---|---|
| npm ci ломался из-за конфликта React 19.3 и @react-three/fiber | Удалён неработающий WebGL стек, обновлён lockfile. Чистый npm ci проходит без force и legacy-peer-deps. |
| Классы цветов не привязаны к Tailwind v4 | Добавлен @theme, сохранены исходные значения цветов. |
| Глобальные стили вне слоёв отменяли отступы и фоны Tailwind | Базовые стили перенесены в @layer base; шрифты не менялись. |
| Резервный фон всегда закрывал hero-видео | Удалён перекрывающий фон; исправлен порядок слоёв. |
| Блокирующий прелоадер показывал случайный прогресс | Главная монтируется сразу, фон-видео загружается параллельно. |
| Ленивая загрузка видео наблюдала несуществующий элемент | Наблюдается постоянный контейнер; видео включается по видимости и приостанавливается вне экрана. |
| Фото авторов не рендерились из-за hideOnLoad | Изображение рендерится сразу, ошибки получают заглушку. |
| Много отсутствующих изображений/видео | SafeImage и SmartMedia с резервным отображением; полный перечень путей для загрузки. Реальные кадры не подменены выдуманными. |
| Карточки горизонтальной ленты выглядели кликабельными, но были div | Реальные ссылки на существующие серии. |
| /work/неизвестное зависал на Loading | Серверная проверка slug, HTTP 404 и ссылки на главную/портфолио. |
| Кнопка заказа одежды ничего не делала | Переход к брифу с выбранным объектом и размером. Онлайн-оплата не имитируется. |
| Шаблонные цены, мерки, тиражи и клиенты выдавались за факты | Неподтверждённые данные убраны; объекты 002/003 обозначены как архивные концепты. |
| Форма показывала успех без отправки | Настоящий серверный endpoint, подтверждение провайдера, ошибки, сохранение брифа и копирование. |
| Контакты @hideki и hello@hideki.studio были неподтверждёнными | Настраиваемые контакты без ссылки на чужой аккаунт по умолчанию. |
| Кнопка звука меняла только подпись | Кнопка в hero действительно меняет muted у главного видео. |
| / перехватывался даже внутри текстового поля | Исправлен поиск; можно вводить слеш в брифе/поиске. |
| Мобильная навигация и доступность | Escape, состояние кнопки, перенос фокуса и цикл Tab; видимый клавиатурный фокус. |
| Декоративные анимации могли мешать пользователю | prefers-reduced-motion; нативный скролл на touch; уменьшенные reveal-переходы. |
| Студия описывала дисциплины, но не объясняла покупку | Пакеты, бюджет, этапы, FAQ и переход к выбору съёмки. |

Анимации: плавное появление текста и изображений, короткий сдвиг карточек, масштабирование фото при наведении, переходы навигации. 3D-мотив заменён фотографической композицией, без зависимости от WebGL и внешнего HDR. Исходная палитра, системный sans-serif и моноширинный шрифт сохранены.

## Проверка

Чистая установка npm ci, TypeScript и production build прошли. Playwright/Chromium: 16 страниц HTTP 200, три неизвестных пути HTTP 404, отсутствие горизонтального переполнения на проверенных страницах. Проверены фильтр портфолио, переключение вида, выбор пакета, выбранный размер, недоступная отправка без потери брифа, подтверждённая отправка с имитацией провайдера, поиск, меню на телефоне 390×844, RU/EN, fallback изображений. Ошибок JavaScript: 0.

Автозапуск и звук проверены с временным тестовым MP4: собственного showreel в архиве нет. При reduced motion видео приостановлено и доступно ручное управление. Скриншоты desktop/mobile визуально просмотрены. Фактическая доставка в Telegram НЕ проверена: настройки получателя не предоставлены. Дополнительно endpoint проверен на неверные поля, большой текст, honeypot, отсутствие конфигурации, имитацию успеха, сбой провайдера и лимит обращений. Эти проверки не означают аудит безопасности всей инфраструктуры.

## Что осталось перед запуском

1. Заполнить реальные контакты и подключить Telegram-получателя. С внешнего устройства отправить один тестовый бриф и убедиться, что он дошёл.
2. Загрузить showreel и обложку; заменить демонстрационные серии реальными кадрами и правильными авторами. Имена клиентов публиковать только если разрешено.
3. Подтвердить стоимость и состав пакетов, срок результата, условия бронирования, использования материалов и отмены. 80 000 ₽ и объёмы пакетов — предложенные условия.
4. Добавить сведения об операторе и документы обработки данных, согласованные с реальным устройством бизнеса.
5. Проверить опубликованный адрес на реальном iPhone/Safari и Android: autoplay, кадрирование лиц, скорость загрузки мобильной сети. В среде проверен Chromium, не Safari.
6. Подключить измерение посещений и целей после выбора инструмента и условий обработки. Первые показатели: переход к пакету, начало брифа, реально доставленная заявка, квалифицированная заявка и бронирование. Не оценивать результат только по просмотрам главной.

До загрузки файлов портфолио явно обозначено как предпросмотр структуры. Это честная промежуточная версия, а не подтверждённый кейсбук.
