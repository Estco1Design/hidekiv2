# HIDEKI — обновление и готовность к запуску

В проект установлены 10 навыков в `.agents/skills/`, с файлами правил, примерами, лицензиями и SHA исходных репозиториев в `sources.json`. Навыки — инструкции для разработки; они не подключаются как скрипты к браузеру. Motion, Three.js, Better Auth и SQLite добавлены как реальные зависимости приложения. Supabase не подключён: текущая база SQLite.

## Что работает в этой версии

- Новая главная, страницы студии, команды и магазина; обновлённая навигация и футер.
- Заставка с отсчётом 0–100, пространственными орбитами, вспышкой и закрытием затвора. Процент относится к вступительной последовательности, а не к загрузке файлов. Можно пропустить или нажать Escape; reduced motion пропускает вступление. Звук щелчка включается только кнопкой зрителя. Вступление показывается один раз за сессию браузера.
- `/account` называется «Личный кабинет». `/archive` остаётся архивом концептов магазина — это другой раздел, не пользовательские данные.
- Настоящий вращаемый WebGL-манекен: шея, грудь, талия, бёдра, рост и внутренний шов. Линии и подписи не скрываются за моделью, вес объясняется отдельно. Доступны drag и range с клавиатуры. Это учебная геометрия, не персональный скан или точный прогноз посадки.
- Регистрация, вход, выход, серверные сессии и сохранение профиля мерок. Данные изолированы по ID пользователя; без входа API отвечает 401, неверные значения — 400, чужой Origin — 403.
- «За кадром» (`/private`) проверяет сессию, подтверждённый email и серверный список приглашений. Регистрация сама по себе не выдаёт доступ. Приватные файлы и платное членство пока не реализованы; закрытый раздел не содержит клиентских материалов.
- Магазин: одежда, съёмки и отдельное пустое состояние арт-объектов. Есть собственный маркированный эскиз Black Set, выбор размера и перенос изделия/размера в бриф. Это запрос изготовления, а не checkout: онлайн-оплата не подключена.
- Учёт отсутствующих медиа до запроса в браузере; при добавлении файлов запускайте `npm run build` / `npm run dev`, которые пересоздают индекс.
- Favicon, OG-изображение, canonical, sitemap, robots, уникальные метаданные. Кабинет, вход и закрытый раздел не индексируются; демонстрационное портфолио помечено noindex до загрузки настоящих работ.

## Настройка и запуск

Node.js 24 LTS. Из `/workspace/hidekiv2`:

```bash
node scripts/setup-local-env.mjs
XDG_CACHE_HOME=/workspace/.cache npm_config_devdir=/workspace/.cache/node-gyp npm ci --cache /workspace/.npm-cache
# Заполните локальные переменные; .env.example теперь существует.
npm run setup:auth
npm run typecheck -- --incremental false
npm run check:inquiry
node scripts/check-private-access.cjs
npm run build
npm start
```

`setup:auth` применяет необходимые миграции Better Auth 1.7.7 и повторно запускается без удаления базы. Профиль мерок создаётся при первом запросе API. Локальная SQLite находится в игнорируемой `.local/`. `.env.local` содержит случайный секрет только для разработки, не включён в Git. Нельзя использовать его как общий production-секрет или публиковать файл.

Локальные браузерные проверки: `npm run check:browser` при запущенном production-сервере на localhost:3000. Нужны Python Playwright и `/usr/bin/chromium`. Они проверяют реальную регистрацию, вход, выход, сохранение/перезагрузку мерок, изоляцию аккаунтов, валидацию, Origin, 3D, фильтры, размер → бриф, маршруты, мобильное меню и reduced motion. Тесты используют адреса @example.test, не реальные контакты. Для тестовой среды держите Resend/Telegram отключёнными. Тестовые аккаунты удаляются после проверки; пароль не сохраняется в отчёт.

## Обязательные данные перед публичным запуском

1. Реальный HTTPS-домен: одинаковые `BETTER_AUTH_URL` и `NEXT_PUBLIC_SITE_URL`; уникальный `BETTER_AUTH_SECRET` минимум 32 символа в защищённых настройках хостинга. После публичных переменных повторить сборку.
2. Постоянный writable volume `HIDEKI_DATA_DIR`, резервные копии и один экземпляр Node для текущей SQLite. Для serverless, нескольких реплик или Supabase нужна отдельная миграция адаптера/данных. Не размещать SQLite в ephemeral filesystem.
3. Подтверждённые публичные email/Telegram/Instagram. Сейчас они отсутствуют, поэтому ссылки скрыты. Реальную доставку заявок включают `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Без них корректно возвращается 503; пользователь может скопировать бриф, но пока нет опубликованного адреса получателя.
4. Для писем аккаунта: `RESEND_API_KEY`, `HIDEKI_EMAIL_FROM` с верифицированным доменом отправителя, доступ к api.resend.com. Код восстановления пароля и подтверждения email подготовлен; без доставки эти возможности недоступны. Реальные письма не отправлялись и не проверялись.
5. Приглашения «За кадром»: `HIDEKI_PRIVATE_EMAILS` — список разрешённых email через запятую. Пользователь должен подтвердить email через письмо. Список не отправляется клиенту. Для материалов потребуется отдельное приватное хранилище и проверка владельца каждого проекта/файла; не класть клиентские материалы в `public/`.
6. Согласовать состав пакетов/цены из исходного проекта, фотографии изделия, авторские работы и права на публикацию. В репозитории имеются только демонстрационные текстуры, а большинство файлов портфолио отсутствует. Подставлять чужие съёмки или выдавать концепты за реальные проекты нельзя.
7. Официальные источники Александра Хидеки: социальные профили, статьи, интервью и разрешённые изображения. Имена и роли взяты только из текущего репозитория. Поисковый запрос и сайт документации Better Auth получили сетевой 403; источники скачивания навыков GitHub доступны. Исследование соцсетей и прессы не завершено без подтверждённых ссылок, публикации не выдуманы.
8. Юридическое имя/контакт оператора, сроки хранения, удаление данных, условия заказа, возврата и использования материалов. `/privacy` описывает поведение приложения и открыто сообщает, что полной юридической политики пока нет. Это не готовый юридический документ.

## Аудит и ограничения проверки

Браузерные результаты: `qa/browser-results.json`, screenshots в `qa/`. TypeScript, API с mock Telegram, private-access правила и production build проверены. Вспомогательный SEOmator установлен вне проекта в `/tmp/hideki-audit-tools`. Локальный SEO-аудит не подтверждает HTTPS/TLS, CDN, production CSP или реальные Core Web Vitals. Его попытка crawl охватила только главную, поэтому 7 основных страниц проверены отдельными запусками (XML в `qa/seo/`). Русскоязычный подсчёт слов в этом CLI занижен; не следует менять содержимое ради искусственного score.

До запуска проверить HTTPS и cookie-флаги на реальном домене, защиту от ботов/спама на уровне хостинга, доверенные proxy IP и общий rate limiter заявок при масштабировании. Добавленные headers подтверждаются локальными HTTP-запросами; production CSP с nonce требует отдельной проверки совместимости Next.js. Полной независимой проверки безопасности и производительности публичного deployment пока нет.

В черновике облачной среды сохранены обновлённые install_script и start_skill, а в пользовательский allowlist добавлены api.telegram.org и api.resend.com с сохранением preset package_managers. Сохранение черновика не применяет сетевые изменения к текущему экземпляру: для будущих задач нужно проверить и сохранить настройки, затем опубликовать среду.

Сайт не был опубликован автоматически. Работающий local build и сохранённый черновик среды не означают production-публикацию.
