# Проверка безопасности HIDEKI

Проверены TypeScript/React/Next.js, обработчики входа и мерок, локальная SQLite, контактная форма и конфигурация headers. Проверка локальная, без production-проxy и внешних аккаунтов.

## Исправлено / безопасные границы

- `src/app/api/measurements/route.ts`: сессия проверяется в каждом GET/PUT, SELECT/UPSERT ограничен ID текущего пользователя, SQL параметризован, PUT проверяет Origin и значения. Браузерный тест двух аккаунтов подтвердил изоляцию.
- `src/lib/auth.ts`: Better Auth вместо самодельных паролей/сессий, минимальная длина пароля 12, ограничение запросов хранится в базе. Cookie управляются библиотекой. Не отключены CSRF/Origin проверки.
- `src/lib/private-access.ts`, `src/app/private/page.tsx`: закрытый уровень требует подтверждённого email и явного приглашения. По умолчанию доступ никому не выдан. Публичный список приглашений или флаг доступа в localStorage отсутствуют.
- `.gitignore`: база и секреты игнорируются. Клиент получает только публичные контакты и наличие настроенной доставки, без значений секретов.
- `next.config.js`: nosniff, запрет встраивания во frame, referrer policy, отключение доступа к камере/микрофону/геолокации.

- `package-lock.json`: npm audit выявил уязвимости исходных Next.js/sharp/source-map-js. Совместимое обновление установило Next.js 16.4.0, sharp 0.35.5 и source-map-js 1.2.2. Повторный npm audit: 0 известных уязвимостей. Это не доказательство отсутствия всех ошибок безопасности.

## Остающиеся требования

1. **Высокий приоритет, условие deployment.** SQLite должна жить на постоянном закрытом volume. Иначе после redeploy аккаунты/мерки могут быть потеряны. Текущая база подходит одному экземпляру, не multi-replica/serverless. Это архитектурное ограничение, не обнаруженная утечка.
2. **Высокий приоритет, запуск формы.** `src/app/api/inquiry/route.ts` использует process-local Map и x-forwarded-for для лимита. На публичном хостинге необходимы доверенная цепочка proxy и общий anti-abuse limiter. Исходная проблема задокументирована; реальная доставка без токена не включается.
3. **Высокий приоритет, приватные материалы.** Сейчас отсутствует защищённое файловое хранилище и связь файла с владельцем проекта. Не размещать клиентские файлы в `public/`. Закрытая страница пока не хранит и не отдаёт материалы.
4. **Средний приоритет, эксплуатация аккаунтов.** Resend, подтверждение email и восстановление пароля подготовлены, но реальная доставка не настроена и не тестировалась. Для закрытого уровня нужен verified email; без провайдера доступ остаётся закрытым.
5. **Средний приоритет, production hardening.** Проверить HTTPS cookie, origin и CSP на реальном домене. Локальное HTTP не является TLS-уязвимостью production. CSP/HSTS нельзя считать настроенными лишь по результатам локального CLI.
6. **Запуск и приватность.** Политика обработки данных требует юридических данных оператора и процесса удаления/retention. Само наличие `/privacy` этого не заменяет.

Реальные пароли/токены/сессионные cookies не включены в отчёты. Тесты не отправляли сообщения настоящим получателям. Тесты не заменяют независимый security review публичного deployment.
